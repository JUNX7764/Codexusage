# 官方账号用量接口核验

日期：2026-11-06 · 性质：只读能力核验 · 状态：当前环境可用，覆盖边界待验证

## 结论

本机 Codex CLI 0.161.0 的 App Server 可通过当前 ChatGPT 登录态成功读取账号信息及账号 Token 活动。累计 Token 和每日桶均返回非空结果；每日桶之和与累计值相等。未启用实验能力的连接也可调用此接口。

这证明该入口在受测环境可用，尚不能证明覆盖所有第三方 harness、其他设备、云端使用或所有套餐。统计值与范围不能直接等同于 Codex 5 小时／7 天额度桶。

本报告记录结构与核验结果，实际邮箱、账户标识和个人用量数值不写入项目文档。

## 方法

1. 使用本机 CLI 导出协议 schema，确认参数和响应结构。
2. 建立独立临时 App Server stdio 连接，关闭该连接的 analytics。
3. 仅发送 `initialize`、`initialized`、`account/read` 和 `account/usage/read`；账号读取明确设置 `refreshToken: false`，用量读取不传 `threadId`。
4. 分别在 `experimentalApi: true` 与 `false` 的连接中验证。
5. 原始响应只在核验脚本内存中处理；输出过滤后的字段、计数、耗时与结果核对。服务 stderr 不持久化、不直接打印。
6. 两次核验结束后独立进程正常退出。未创建 thread、未发起 turn、未执行模型推理、登录或重置卡操作；应用源码与运行中的 CodexUsage 未作替换。

## 已验证结果

| 检查项 | 结果 |
|---|---|
| CLI 版本 | 0.161.0 |
| 初始化 | 两种能力设置均成功 |
| 当前账号类型 | `chatgpt` |
| 当前套餐字段 | 返回 `plus` |
| 邮箱 | 返回非空字段；本报告不记录其值 |
| 账号用量方法 | `account/usage/read` 成功 |
| 实验能力 | 当前版本在 `experimentalApi: false` 下也成功 |
| 累计 | `summary.lifetimeTokens` 为非空非负整数 |
| 每日桶 | 返回非空数组，字段为 `startDate`、`tokens` |
| 一致性 | 返回桶之和等于返回累计值；第二次结果相同 |
| 数据质量 | 第二次响应中无重复日期、无负数日用量 |
| 附加摘要 | 返回峰值日用量、最长运行回合时间、连续使用天数等字段 |
| 账号级输入／输出拆分 | 本次账号汇总没有提供 |
| 工具／模型拆分 | 本次账号汇总没有提供 |
| `threadUsage` | 此次请求为账号级，不构成线程用量能力验证 |

账号读取约 1.5—1.6 秒；账号用量读取约 1.8 秒。以上为两次顺序调用样本，不能代表延迟分布或服务 SLA。

两个短时进程结束前的 RSS 单次快照约 48,640—48,800 KiB，进程累计 CPU 时间约 0.03 秒。该数值包含 App Server 自身，不等于功能接入后的增量内存；未测峰值、长期后台唤醒或实际电量变化。

## 尚不能确认的范围

- 当前响应的最新日期早于核验本地日期，统计时区、今日数据是否延后、刷新延迟尚未确定；缺少今天的桶不能解释为今天用量为零。
- 日期数组可能稀疏；没有出现的日期是否代表零、无数据或覆盖缺失尚未确定。
- 最早返回日期不等于账号创建日，也不能单独证明包含所有历史。
- 汇总字段的缓存 Token、重试、子 Agent、推理 Token 等计量定义尚未与本地日志逐项对账。
- 本次未通过受控调用验证各第三方 harness，也未验证其他设备、云端和不同工作区的覆盖。
- 未验证 API key 模式、其他套餐、旧 CLI 版本或缺失方法的实际降级；官方文档所述支持范围与本次实测范围分开记录。
- 每日总量的自洽只能证明响应内部一致，不能证明对外部真实消耗没有遗漏。

## 产品建议

1. 将该接口作为账号累计与日趋势的优先候选，先验证范围和时间口径；避免在能取得可靠官方数据时重复建设同范围的历史日志回填。
2. 工具、模型、输入和输出继续属于本机可读明细。账号总览与本机明细分开标明范围，不相加、不强制相等。
3. 用户确认的周期行原位展开体验继续保留；若账号接口没有相应维度，不将本机模型拆解伪装为账号总额的完整分解。
4. 暂不依此做今日实时消耗或 Token 与额度百分比的换算。
5. 接入设计评估短时读取、连接复用和现有原生网络层的可行性；本次探测使用独立进程，不要求成品增加常驻 App Server。
6. 后续真实订阅调用、跨设备或第三方验证单独安排；本次只读结果可以进入可行性结论，不能进入完整兼容名单。
