# CodexUsage 用量总览 PRD

文档版本：1.1 · 日期：2026-11-06 · 状态：用户已授权开发 · 目标应用版本：v1.1.0

2026-11-06 用户指定新建 Terra high 开发会话执行本稿，由当前主会话验收。开发使用独立 worktree／分支，正式合并、安装替换和发布在验收后安排。

本稿作为下一阶段开发的产品评审稿。重置卡与 Tibo 沿用现状；Tibo 下方依次展示「用量情况」「用量简析」「工具明细」。周期行保留原位模型开合，日图保留即时悬停与「较昨日／较前7天」，底部版本入口及更新逻辑沿用当前实现。

## 1. 产品目标与范围

CodexUsage 是面向 Codex 订阅用户的原生菜单栏工具。本版回答三类问题：账号还剩多少额度、官方记录了多少用量、本机主要通过哪些工具与模型使用。

| 层级 | 内容 | 来源与含义 |
|---|---|---|
| 账号与额度 | 套餐、邮箱、5 小时／7 天剩余额度及重置时间 | 当前登录账号的数据 |
| 用量情况 | 今天、近 7 天、近 30 天的总量／输入／输出及模型 | 本机已支持来源的 OpenAI 用量，可包含 API 和订阅归属未确认的记录 |
| 用量简析 | 累计 Token、近 30 天日图、较昨日／较前7天 | 官方账号 Token 活动接口返回的统计 |
| 工具明细 | Codex、Proma、Claude Code、Hermes 的来源分布 | 与本机用量表使用同一份统计快照 |

「用量简析」与「用量情况」使用不同统计范围，各自展示、不相加、不强制配平。来源口径在文档说明；界面不设置「统计范围」入口或替代徽标。工具日志中的模型名不能证明某次调用使用了当前账号订阅。

本版采用官方累计作为累计展示来源；本机表保留三个近期周期。账号累计作为独立数值，不作为本机周期表的第四行。模型展开属于本机周期行。

本版交付包含以上统计展示、来源状态、交互和降级。系统通知、费用估算、耗尽时间预测、导出、多设备同步、自定义日志设置页及本机全历史累计另行评估。

## 2. 现状与已验证能力

当前实现已支持账号额度、邮箱和套餐文字、重置卡及 Tibo，以及分开的 Codex／外部近 30 天统计；外部来源尚未在 UI 中逐工具展示。

2026-11-06 只读核验确认：本机 Codex CLI 0.161.0 在当前 ChatGPT Plus 登录态下，可调用 `account/read` 和 `account/usage/read`。账号累计及每日数组非空，日数组之和与累计一致；`experimentalApi: false` 的连接也成功。详情见[官方接口核验报告](12-official-usage-verification.md)。

已确认的限制：本次账号汇总没有工具、模型、输入／输出拆分；最新日期早于核验本地日期；统计时区、延迟及第三方覆盖尚未确认；稀疏日期的客户端显示行为已有固定源码证据，不能视为后端永不变化的契约。当前成功样本不能代表全部套餐、客户端或历史。

接口协议另有指定会话的估算拆分字段，尚未进行真实请求验证。本版账号明细不依赖该能力。

### 3.1 顶部身份

- 应用图标统一，标题为「Codex 用量」，套餐使用旁边的文字标签，如 `PLUS`、`PRO`；标签形状和样式一致。
- 套餐依据实际账号／额度响应，不根据额度大小推断；其他返回名称安全展示，过长可截断查看全文，缺失时隐藏。
- 邮箱使用标题下方的次要文字。当前本地解析或经核验的账号响应可提供邮箱；缺失时隐藏该行，不填演示值。
- 所有账号响应遵守现有身份与请求代际隔离；切换账号先清空上一账号的套餐、邮箱和官方统计缓存展示。

### 3.2 原有板块

重置卡与 Tibo 重置动态沿用当前内容、内部布局、顺序、动作、状态、链接和错误表现。包含多卡明细、到期提示、用卡确认、未知结果核对及预估时间语义。对这两块使用现有固定数据预览作为视觉和行为基线。

### 3.3 按套餐与实际能力展示额度窗口

额度区展示当前账号适用的窗口。2026-11-06 核对的[官方说明](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan)明确 Pro 当前没有 5 小时限额；用户截图中的 `PROLITE` 显示有效 7 天额度，同时将缺少 5 小时数据显示成解析错误。当前代码为两个窗口预设缺失错误，尚未区分套餐能力。

推荐界面：已确认没有 5 小时窗口的账号，在面板及菜单栏中只显示有效的 7 天窗口；其他适用双窗口的账号继续展示两行。重置时间列跟随实际窗口行，不保留不适用窗口的空进度条。

| 窗口状态 | 判定与展示 |
|---|---|
| 有有效额度 | 使用服务端已验证的窗口值、时长和重置时间正常展示；有效值优先于套餐默认规则 |
| 已确认不适用 | 正常状态，隐藏该窗口行；不显示错误、过期提醒或虚构百分比 |
| 尚未取得／能力未确认 | 中性灰色「暂未提供」，按需在悬停说明；不推断为无上限或剩余 100% |
| 请求失败 | 保留同账号旧数据和原成功时间，给出简短可读提示，沿用真实失败的重试与过期处理 |
| 存在但数值非法 | 作为数据异常处理，保留诊断与正常窗口；不能借套餐规则跳过字段校验 |

- 不适用的判定优先使用明确的服务端能力信息。兼容旧响应时，要求请求成功、可识别的套餐规则与窗口缺失形态相符，并有合法额度结构；不得把任意缺失字段都判作不适用。
- `pro` 与截图中的 `prolite` 需用对应合法响应夹具分别验证；套餐别名映射有来源和核验日期，未知名称保持能力未确认。当前没有受测 Pro 原始响应，开发需补足结构证据。
- 已知套餐若实际返回有效 5 小时额度，则按真实有效数据展示，不因套餐名强制隐藏。窗口时长按明确字段识别，不假定 primary 永远是 5 小时。
- 状态由双窗口切到单窗口时，清除已不适用窗口的旧额度、旧错误及旧新鲜度标记；重新出现有效窗口时正常恢复。
- 某一窗口不适用不影响另一个窗口的成功时间，也不导致总体失败。无任何有效窗口且能力未确认的空响应仍是异常或未知，不能报告完整成功。
- 技术解析信息保留在脱敏诊断中；普通界面使用简短中文状态。不适用窗口的缺失不产生红色报错。
- 原型 v0.8 中 Plus 的双窗口布局仍适用；另增加 Pro 单窗口视觉与菜单栏夹具作为开发验收，统计区与版本更新逻辑按本稿保持。

## 4. 用量情况

### 4.1 周期表

该板块紧随 Tibo 重置动态。标题为「用量情况」，保留原统计板块的线性符号与整体开合按钮；来源口径见文档，不设置统计范围入口。列为「周期 / 总量 / 输入 / 输出」，周期为今天、近 7 天、近 30 天。输入包含当前规则计入的缓存 Token，沿用现有来源计量定义。

- 今天：本地当天 00:00 至当前统计时点。
- 近 7 天：今天及此前 6 个本地日历日。
- 近 30 天：今天及此前 29 个本地日历日。

每行合并已支持本机来源的对应周期。统计范围在文档中说明：本机 OpenAI 模型统计，可能包含 API、不同账号或订阅归属未确认的记录。

### 4.2 周期行展开

- 保留整行按钮、展开箭头与键盘操作。点击后模型明细紧随该行，再次点击收起。
- 三个周期独立，可同时展开；板块整体收起不清除周期选择。
- 模型明细按原始总量降序，同值按原始模型 ID 排序；同一 ID 跨工具合并，不凭相似名称合并不同模型。
- 模型列与总量／输入／输出对应对齐；长名称截断并可读取全文。
- 缺模型但已计入的 Codex 记录归入「未知模型」；外部来源继续遵守模型识别规则。
- 零用量可展开查看「本周期暂无用量」；读取失败与零分开。
- 数据刷新、关闭重开保留本次进程的选择与合理滚动位置；应用重新启动恢复默认。
- 点击周期只控制该行明细，不改变账号图表和工具周期。

## 5. 用量简析

### 5.1 累计

- 标题为「用量简析」，左侧采用暖橙色三根竖条符号；标题及右侧箭头可独立折叠，默认展开。主数值使用官方累计，采用 K / M / B 缩写，与「累计 Token」紧邻同一行。
- 悬停或键盘聚焦可读取未缩写总数、来源及最近成功查询时间。
- 累计是接口返回的累计值，不命名为账号创建以来全部消耗，不推断已覆盖所有设备、产品或第三方工具。
- 该数值没有输入／输出或模型展开；工具、模型明细在本机统计区查看。
- 标题区域保留竖条图标、标题和折叠箭头，不设置来源徽标或额外说明入口。
- 其他摘要字段如单日峰值、连续使用天数暂不占默认界面空间。

### 5.2 每日图表

- 图表位于账号累计下方，使用 `dailyUsageBuckets`，范围为「近 30 天」。
- 以最新有效源日期为右端，展示连续 30 个源日期位置；日期轴保留源日期，不另设「近30天 · 截至」说明行，也不改写为本地今天。
- 遵循[官方客户端固定版本的稀疏活动桶显示行为](https://github.com/openai/codex/blob/2c502d8b3d382dd609179164f31396d95deee55c/codex-rs/tui/src/analytics/activity_chart.rs)：非空官方日数组实际返回的最早与最晚日期之间，缺桶按 0 展示；明确零值同样显示 0。最早日期之前、最新日期之后、空数组或来源口径未知时不外推，仍显示缺失。图表与比较共用同一日值规则；该行为不保证后端未来永不变化。
- 当前源日期不能证明完整时，不将其称为完整日，也不通过该图计算今日实时值。
- 累计与图表是同一账号范围，但图表只展示对应 30 天。累计更大属于正常时间范围差异。

### 5.3 鼠标与辅助功能

- 鼠标进入某个日期列，立即高亮并显示即时浮层，例如「11 月 5 日 · 12.60M Token」。不需要点击、不等待系统默认工具提示。
- 命中范围覆盖该日整列，含柱间空隙、零值和缺失日期。左右移动连续更新日期和值；移出隐藏浮层。
- 浮层展示日期、总量及必要状态。缺失显示「暂无数据」，不显示伪造数值。官方没有提供输入／输出时不增加这些字段。
- 浮层覆盖在图表内部，优先置于所选柱的另一侧，不额外预留顶部高度、不拦截日期命中、不越出图表。累计行与最高柱之间保持紧凑间距，保留日期轴。
- 键盘可逐日查看；VoiceOver 可读取同等信息。交互只读取已取得的日数组。

### 5.4 变化比较

图表下方固定保留一条浅灰圆角对比行，左右两项为「较昨日」「较前7天」，中间用细竖线分隔；背景复用重置卡和 Tibo 卡片的动态填充色，保持紧凑圆角。样式沿用用户参考图，演示值为「较昨日 +18%」「较前7天 −6%」。增加值用暖橙色、减少值用绿色，符号与文字同时传达方向。

| 比较 | 规则 |
|---|---|
| 较昨日 | 以图表截至日期 D 为基准：（D 日用量 − D−1 日用量）÷ D−1 日用量 |
| 较前7天 | 截至 D 的 7 个日历日之和，与紧邻之前的 7 个日历日之和比较 |

- 日期轴最右端对应比较基准 D，D 不自动当作本地今天。悬停或键盘聚焦比较项，显示明确日期区间和数据来源；七日项同时说明两组七日总量及「（最近7日总量−前7日总量）÷前7日总量×100%」。
- 比较基准固定为图表截至日期，不随鼠标移动到历史柱而改变；柱的悬停浮层只显示该日值。
- D 为接口最大源日期。日比较使用 D 与 D−1；七日比较使用 [D−6,D] 与 [D−13,D−7]。UTC 仅用于日期标签运算，不将 D 称为本地今天。使用图表相同的范围内稀疏补零规则；范围外缺失、空数据和超过 30 分钟未成功查询时对应项显示「数据不足」，提示写明缺少日期或过期原因。
- 基期零、本期正数显示「由 0 增至 X」，两期均零显示持平；不产生无穷百分比，不用本机记录补齐官方比较。
- 原型使用已知完整的虚构数据展示百分比正常态；真实当前接口的日期完整性仍按核验报告处理。

## 6. 工具明细与覆盖

### 6.1 展示

- 默认折叠；展开后「今天 / 7天 / 30天」位于标题右侧、折叠箭头左侧，使用暖橙色紧凑原生按钮；周期与折叠独立，选择及开合在刷新和本进程关闭重开后保持。
- 每行采用「工具名称 + 占比条 + 总量」，名称左对齐，统一强调色；悬停或聚焦查看输入、输出、占比和来源状态。
- 按未缩写总量降序，同值使用 Codex、Proma、Claude Code、Hermes 的固定顺序。
- 工具行使用文字布局。新增板块与展开操作采用 SF Symbols；界面无需新增工具品牌图片资源。
- 占比只使用本机同周期、同一快照的总量作为分母。全零不算占比，缺失来源明确标记部分数据；占比不代表官方订阅消耗比例。
- 已发现的有效零值来源可显示 0；不存在且没有记录的来源不占默认行空间。失败来源保留行和已有值，状态可见。

### 6.2 当前来源

| 来源 | 读取范围 | 重要边界 |
|---|---|---|
| Codex | 当前指定会话目录的 JSONL／zstd | 共用目录的入口合并，当前不再细分桌面／CLI；登录模式可能混合 |
| Proma | 当前已适配会话和旧版 projects | 并行日志有重复，沿用已验证来源选择 |
| Claude Code | 已识别为 OpenAI 模型的本地记录 | 不包括 Claude 模型本身用量 |
| Hermes | 当前 SQLite 累计行快照与增量 | 可统计模型，但历史日期归属可能为推定 |

四类来源表示已有解析能力，不代表已确认四个工具都使用订阅，或已在每位用户机器上读取成功。

### 6.3 来源说明

来源与兼容边界保留在[用量来源兼容矩阵](14-compatibility-matrix.md)，面板不设置「统计范围」入口或替代长说明。目录未发现不代表未安装；模型名不证明订阅路由。

## 7. 数据一致性与安全

### 7.1 两类数据各自闭合

- 官方累计和日数组遵守其服务端定义；只按已确认字段展示。不同统计时点、账户／工作区或范围的数据不能拼接成一份结果。
- 本机同周期的工具之和、模型之和与本机合计在原始精度下一致。缩写、四舍五入只用于显示。
- 两类数据不作相减来计算所谓遗漏量，也不显示未经验证的覆盖百分比。
- 切换账号重置官方展示和请求代际；本机统计继续按设备记录显示，不随账号误清空，也不标成当前账号专属用量。

### 7.2 现有扫描与迁移

本版的本机统计沿用近 30 天增量扫描，增加工具维度、来源状态和统一结果。本机历史处理围绕近 30 天窗口，官方累计直接使用已验证接口字段。

- JSONL 追加只读新增部分，未变化文件复用缓存；压缩档沿用当前去重规则。
- 来源路径、会话／事件身份和镜像去重规则统一；多个工具共享同一记录时不能重复计数。
- Hermes 累计差分与已有快照不重复相加。首次存量缺少准确日归属、跨日未采样或计数异常时标记推定归日；覆盖详情解释限制，不把推定当作精确日明细。
- 旧缓存缺少工具维度时，可从仍存在的窗口内记录重建；无法恢复的历史维度明确标记，不按比例分摊。
- 部分来源失败保留旧贡献和原成功时间；无旧值标缺失，不当作 0。迁移原子写入，失败可恢复，不破坏原始日志或数据库。
- 所有真实来源只读；测试注入临时根目录与假凭据，认证字段和正文不进入统计状态、报告或提交。

## 8. 更新、状态与降级

| 场景 | 行为 |
|---|---|
| 首次读取 | 各区域独立加载，已有额度和原有板块继续使用 |
| 官方累计非空、日数组为空 | 显示累计，图表显示暂无每日数据 |
| 官方累计为空、日数组可用 | 显示图表，累计显示暂无数据，不把数组总和冒充 lifetime |
| 官方接口不支持／CLI 缺失 | 账号区显示当前环境不支持，仍展示本机区；不要求用户运行终端才能继续使用 |
| 官方查询失败 | 保留同账号旧值和原成功时间，提示失败与重试；无旧值显示暂无数据 |
| 最新日桶早于当前日期 | 日期轴末端及比较提示以最新源日期为准；不将缺少今天解释为今天为零 |
| 官方数据过期 | 以查询成功时间标记过期；源日期与查询时间分别说明 |
| 本机单源或全源失败 | 保留已有统计与来源时间，明确部分数据／失败 |
| 切换账号 | 拒绝旧响应，官方数据与邮箱／套餐跟随当前身份 |

- 官方用量首次打开后台读取，之后与现有 5 分钟任务合并调度；有效缓存期间开合面板只读缓存。
- 「立即刷新」请求各来源重新读取，重复点击合并；图表悬停、折叠、工具周期切换不触发 I/O。
- 官方读取采用 15 秒总超时，失败后等待下一正常周期或手动重试，不形成快速重试循环。
- 官方查询超过 30 分钟未成功视为过期；源数组的最新日期由日期轴末端及比较提示体现，不能用查询成功掩盖源数据滞后。本机沿用现有新鲜度规则。
- 本机值始终放在本机区，不在官方失败时静默填充账号累计或账号图表。

### 8.1 版本号与更新沿用当前实现

- 底部保留「最近尝试刷新 HH:mm」及「版本 <当前构建版本>」。版本来自现有 `BuildInfo.version`，不能由 PRD 版本号代替，也不写死某个发布版本。
- 当前源码基线 `git describe` 为 `v1.0.18`，本次原型以「版本 v1.0.18」展示样式；不据此断言正在运行的安装包版本。
- 点击版本号继续手动检查更新，保留检查中、已是最新、发现新版本、检查失败和版本未知的现有反馈。
- 沿用启动约 20 秒首查、之后每 30 分钟及打开面板时共享节流的自动检查；手动检查继续使用现有强制检查路径。
- 有可安装新版本时，沿用现有更新提示入口；点击后保留面板内更新进度、失败反馈、关闭面板后后台继续及重开恢复进度的行为。
- 下载、校验、安装替换、重启与失败处理沿用现有更新器及脚本。不因本次统计设计更换仓库身份、发布资产选择或安全校验规则。
- 本次功能目标版本为 v1.1.0，版本展示与检查／更新流程继续使用现有机制。开发分支和验收包可以标识为开发版本，正式 v1.1.0 标签与发布资产在验收后产生，不提前触发真实更新。

## 9. 布局、性能与接入约束

- 保持原生 NSPopover、现有暖橙色、字体层级和约 330 pt 宽度；工具文字、列和分段控件适配该宽度。
- 「用量情况 → 用量简析」与「用量简析 → 工具明细」之间各放一条淡色横线：0.5 pt 高、系统动态分隔色、55% 视图不透明度，左右与内容及页头／页脚分隔线对齐。线与两侧等量留白合计仍为原有 8 pt，不增加面板高度；折叠时保留边界，上方卡片及各数据行不新增分隔线。
- 默认「用量情况」与「用量简析」展开、模型行收起、工具折叠；展开与刷新不跳回顶部。
- 沿用现有屏幕高度上限和内容滚动，头尾操作可访问；支持深浅色、降低透明度、键盘和 VoiceOver。
- 每日图只绘制最多 30 个日期位置，交互使用内存结果；关闭面板不执行图表动画或鼠标轮询。
- 官方账号接口比现版增加定期读取，使用统一调度和缓存，不新增高频计时器；本机扫描频率保持现状。
- 开发先确定轻量接入方式，评估短时 App Server、已有连接复用及经过验证的原生网络接入；本 PRD 不要求增加常驻 App Server 或捆绑 CLI。
- 若只能通过增加运行依赖或显著资源开销接入，先交付具体代价评估供确认，再进入该实现。独立探测进程约 48 MiB 的单点读数不能当作成品增量成本或峰值。
- 所有读取后台执行，不发起模型推理。CPU、内存、磁盘、唤醒和电量变化以同环境新旧对比为准，不在实现前承诺百分比。

## 11. 开发交接与评审

用户已授权 Terra high 开发会话执行，完成后由主会话验收。建议开发顺序：

1. 确定官方接入代价、支持版本、日期语义和账号隔离；用可空响应和失败夹具固定接口。
2. 为现有本机统计增加来源维度与状态，保持输入／输出和模型统计口径。
3. 实现账号总览、本机周期展开、工具明细和图表即时悬停。
4. 完成集成、无障碍、屏幕适配、性能及既有板块回归，更新面向用户和开发者的现行说明。

开发拆分需明确文件所有权和接口，避免多个 Agent 同时修改当前主 Swift 文件。实现方案与发布安排在下一阶段确定。

本稿评审以最终布局为准：「用量情况」紧随 Tibo，其后为带竖条图标的「用量简析」及两项对比，再下方是默认折叠的工具明细。即时悬停、周期模型开合和现有版本更新机制均按本文验收。
