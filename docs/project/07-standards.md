# CodexUsage 维护约定

> 状态：当前维护约定。最后核对：2026-11-06。
> 目标是让小项目保持可验证，而不是增加流程文档数量。

## 1. 文档

- 当前行为只维护在 `README.md`、`docs/DEVELOPMENT.md` 和 `docs/project/`。
- `PLAN.md` 与已完成 feature 目录是历史记录，新增当前规格不得只写在这些文件中。
- 行为变化与文档更新放在同一个提交；无法确认的内容标为未知或历史，不补写成已实现事实。
- 不新增空模板、占位符和只为显得完整的流程文档。
- 公开文档与提交信息不写真实凭据、会话正文、个人邮箱或不必要的环境细节。

## 2. Swift 与数据解析

- 外部 JSON 按不可信输入处理：校验类型、有限数值、时间、枚举和必填字段。
- 网络失败保留旧值时必须保留原成功时间，并显示过期或错误状态。
- 账户切换使用身份与代际隔离，拒绝迟到响应覆盖新账户状态。
- 本地会话和数据库原始来源只读；测试通过临时根目录和缓存路径注入隔离真实数据。
- UI 文案不得作为业务逻辑键；可测试的解析和合并逻辑优先写成纯函数。

## 3. 凭据与账户操作

- `access_token`、`refresh_token`、`id_token` 只存在于必要内存和系统既有凭据文件中，不进入日志、状态文件、报告或提交。
- 只有 401 且满足冷却条件时才尝试 OAuth 续期；写回前重新读取、比较并原子替换，保持仅所有者可访问权限。
- 重置卡使用必须确认账户、说明不可逆性并保存原请求 ID；结果未知时不得生成新请求盲目重试。
- 测试使用假凭据，不读取真实 `~/.codex/auth.json`。

## 4. Shell 与发布脚本

- 保持 `set -euo pipefail`，变量正确引用；中文或全角字符相邻时使用 `${var}`。
- 更新只定位目标 Bundle、可执行路径和 LaunchAgent，禁止按名称模糊 kill。
- 停止旧进程前完成下载、校验和暂存；失败必须保留或恢复旧包。
- 普通审查只运行离线测试和语法检查，不直接运行真实更新、发布或 LaunchAgent 操作。

## 5. 修改验收

按影响范围选择测试，但更新、发布或构建脚本变化必须至少执行：

```bash
./build.sh
./CodexUsage.app/Contents/MacOS/CodexUsage --self-test
python3 -m unittest discover -s tests -p '*_test.py'
bash -n build.sh scripts/update.sh scripts/release.sh
```

UI 变化还需固定假数据预览和对应交互回归。联网、真实凭据、真实安装与系统兼容性验证必须单独注明，不能用“离线测试通过”代替。

## 6. 版本与提交

- 提交说明写清问题、根因、修改和验证，避免粘贴大段个人调试流水。
- 用户可感知的新功能使用 minor 版本，兼容性修复使用 patch 版本；安全修复应明确标注。
- 发布前工作区必须干净且 HEAD 与预期远端一致；正式发布只从确认的提交和完整资产产生。
